# 더치페이 최소 송금 계산기

여러 명이 함께 쓴 돈을 정산할 때 **누가 누구에게 얼마를 보내면 되는지**를
적은 송금 횟수로 알려주는 파이썬 프로그램입니다.

- 항목마다 결제자와 참여자가 달라도 각자 쓴 만큼만 부담하도록 계산합니다.
- n명이면 송금은 최대 n−1번으로 끝납니다.
- 파이썬 표준 라이브러리만 사용하므로 따로 설치할 것이 없습니다. (파이썬 3.11, 3.12, 3.13에서 실행 확인)

## 파일 구성

| 파일 | 내용 |
|---|---|
| `dutchpay.py` | 본 프로그램 (입력, 잔액 계산, 송금 매칭, 출력) |
| `optimal.py` | 검증용: 완전 탐색으로 실제 최소 송금 횟수 구하기 |
| `test_dutchpay.py` | 테스트 12개 (미리 구해 둔 정답과 비교, 무작위 1,000건 검사 등) |
| `experiment.py` | 실험: 탐욕 알고리즘 결과와 실제 최솟값 비교 |
| `data/trip.csv` | 예시 1: 4명 여행 (계획서 예시) |
| `data/mt.csv` | 예시 2: 6명 MT (나누어떨어지지 않는 금액 포함) |
| `data/error_example.csv` | 예시 3: 일부러 틀리게 쓴 입력 (오류 검사 확인용) |

## 실행 방법

명령 프롬프트(macOS는 터미널)를 열고 이 폴더로 이동한 뒤 실행합니다.
macOS·리눅스에서는 `python` 대신 `python3`을 입력합니다.

```
python dutchpay.py                  메뉴에서 선택 (예시 / CSV 파일 / 직접 입력)
python dutchpay.py data/trip.csv    CSV 파일을 바로 계산
python test_dutchpay.py             테스트 실행
python experiment.py                실험 실행 (몇 초 걸림)
```

## CSV 파일 형식

첫 줄은 제목, 둘째 줄부터 한 줄에 결제 1건씩 적습니다.
참여자는 띄어쓰기(또는 `/`)로 구분합니다.

```
항목,금액,결제자,참여자
숙소,160000,A,A B C D
저녁,90000,B,A B D
```

- 엑셀에서 만들 때는 "CSV UTF-8(쉼표로 분리)"와 기본 "CSV(쉼표로 분리)" 형식 모두 읽습니다.
- 메모장 등으로 직접 적을 때 금액은 `160000`처럼 쉼표 없이 적습니다.
  (`160,000`이라고 적으면 칸이 나뉘므로 프로그램이 몇 번째 줄인지 알려 줍니다.)

## 실행 예시 (`data/trip.csv`)

```
■ 사람별 잔액  (잔액 = 낸 돈 - 부담액)
  사람          낸 돈      부담액        잔액
  A           160,000      79,000     +81,000   받을 사람
  B            90,000      79,000     +11,000   받을 사람
  C            24,000      49,000     -25,000   보낼 사람
  D            12,000      79,000     -67,000   보낼 사람
  검산: 잔액의 합 = 0

■ 송금 방법
  1. D → A   67,000원
  2. C → A   14,000원
  3. C → B   11,000원
  항목마다 따로 보낼 때 11회  →  이 프로그램 3회
```

## 계산 방법

1. **잔액 계산**
   부담액 = Σ(항목 금액 ÷ 그 항목의 참여 인원), 잔액 = 낸 돈 − 부담액.
   잔액이 +면 받을 사람, −면 보낼 사람입니다.
   나누어떨어지지 않아 남는 몇 원은 그 항목의 결제자가 부담합니다.
2. **송금 매칭 (탐욕 알고리즘)**
   잔액이 가장 큰 사람과 가장 작은 사람을 짝지어, 둘 중 작은 금액만큼 송금시킵니다.
   한 번 송금할 때마다 최소 한 명의 잔액이 0이 되고, 마지막 송금에서는 남은 두 사람이
   함께 0이 되므로 n명이면 최대 n−1번에 끝납니다.

## 테스트와 실험 결과

- `test_dutchpay.py`: 테스트 12개 모두 통과
- `experiment.py` (난수 씨앗 2026 고정, 인원 3~10명, 인원수마다 1,000건)
  - 실험 A (금액이 다양한 무작위 결제 내역 8,000건): 7,996건에서 탐욕 결과 = 실제 최솟값
  - 실험 B (잔액이 1,000원 단위로 떨어지는 경우): 4명 이하는 100% 일치,
    10명에서는 76.8%만 일치하고 최대 2회 더 많았음

## 한계

- 탐욕 알고리즘은 실제 최솟값을 항상 보장하지는 않습니다.
  예: 잔액이 A +5,000 / B +4,000 / C −4,000 / D −3,000 / E −2,000 이면
  탐욕은 4회, 실제 최소는 3회입니다.
  (송금 횟수를 최소로 만드는 문제는 일반적으로 NP-난해 문제로 알려져 있습니다.)
- 화면(GUI) 없이 터미널에서만 동작합니다.
